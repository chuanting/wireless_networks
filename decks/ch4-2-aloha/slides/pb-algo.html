【3.5 分钟】 算法每个时隙做两件事。第一，决定发不发：每个积压的分组（新到的也算），以概率 q = min(1, 1/ñ) 发送。第二，看反馈，更新估计：如果这个时隙空闲或成功，ñ 变成 ñ + λ − 1，但不小于 λ；如果碰撞，ñ 变成 ñ + λ + 1/(e − 2)，常数 1/(e − 2) 约等于 1.392。两条规则里都有“+λ”，因为每个时隙平均新来 λ 个分组；λ > 0 时用正数初始化，可以避免除零。 下面的表是一个例子：λ = 0.3，开始时 ñ = 4，三个时隙的反馈依次是碰撞、空闲、成功。时隙 1：q = 1/4 = 0.25；碰撞，ñ = 4 + 0.3 + 1.392 = 5.692。时隙 2：q = 1/5.692 ≈ 0.176；空闲，ñ = 5.692 + 0.3 − 1 = 4.992。时隙 3：q ≈ 0.200；成功，ñ = 4.992 + 0.3 − 1 = 4.292。注意每一行的 q 是用这一行开头的旧估计算的；迭代计算建议保留未舍入的值。 规律：碰撞说明发的人多，估计往上调，下一个时隙每个分组发得更少；空闲或成功，估计往下调。要注意估计的更新不是真实积压的更新：空闲时 ñ 下降，并没有分组离开；碰撞后 ñ 上升，也不是凭空多了分组，旧的分组互撞并不产生新分组，估计的上调只是从反馈得到的信息修正。真实的积压由新到达和成功离开决定。 为什么偏偏是减 1 和加 1.392？下一页解释。 [λ 不知道时，可以在更新里用 1/e 代替 λ；教材指出这样在 λ < 1/e 时仍然稳定。]
