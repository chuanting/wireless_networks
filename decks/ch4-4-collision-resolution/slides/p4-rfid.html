场景：仓库门口，读写器一问，范围里的标签同时回答——撞了。标签彼此听不见，没法先听后说。

按编号分：读写器问“编号以 0 开头的回答”，还撞就问“以 00 开头的”……每撞一次，前缀加一位：这就是树形分裂，只是用编号代替了抛硬币。

例：标签 0010、0111、1100：问“所有”撞，问“0…”撞，再问“00…”“01…”“1…”各一个：5 次问完。

标准里：ISO/IEC 18000-6 的 B 类标签用二叉树防碰撞：每个标签一个计数器，撞了就随机加 0 或 1，和第二部分是一个思路。

用硬币、到达时间还是编号来分，道理都一样：每撞一次，一分为二。

【3 分钟】 冲突分解在今天最典型的应用，是 RFID 射频识别：读写器一次清点很多标签，比如仓库门口一托盘货物，几十上百个标签。 读写器发一个询问，范围里的标签同时回答，撞了。标签之间彼此听不见，没法先听后说；但读写器是一个天然的“裁判”，0、1、e 的反馈由它统一判断、统一下发，正好满足上一页的前提。 一种做法叫查询树：按编号分。读写器问“编号以 0 开头的标签回答”；还撞，就问“以 00 开头的”……每撞一次，前缀加一位。这就是树形分裂，只是用编号代替了抛硬币。 看左边的例子：三个标签 0010、0111、1100。问“所有标签”，撞了；问“0 开头的”，0010 和 0111 撞了；问“00 开头的”，0010；问“01 开头的”，0111；问“1 开头的”，1100。5 次问完。 另一种做法和第二部分的计数器一模一样：ISO/IEC 18000-6 的 B 类标签，每个标签一个计数器，计数器为 0 就回答，撞了就随机加 0 或 1。 所以不管用硬币、到达时间还是编号来分，道理都一样：每撞一次，一分为二。
