时隙 3 前：c(A,B,C) = (0,1,1)，d = 3。A 成功后，B、C 的 c 和 d 各是多少？

【必讲 · 4 分钟 · 先判断再揭晓】 先显示规则与问题，表格暂不出现。给学生 1 分钟计算：时隙 3 成功后，B、C 的 c 都从 1 变成 0，d 从 3 变成 2，所以时隙 4 两者一起发。请一位学生解释，再点击显示完整计数表，按列核对。 上一页的栈，在真实的网络里放在哪里？没有集中的栈：每个节点只记自己的信息，大家听到同样的反馈，所以栈的状态是一致的。 每个有分组在等的节点，给自己的分组记一个计数器 c：在我这一组前面，还有几组在等着。c = 0，说明我这一组就在栈顶，这个时隙该我发。另外所有节点，包括没有分组的，共用一个计数器 d：栈里一共还有几组。d 等于 0，分解期结束。 更新规则：碰撞——栈顶这一组一分为二，所以 c = 0 的分组抛硬币：正面仍在栈顶，c = 0；反面到第二层，c = 1。c 大于 0 的分组，前面多了一组，c 加 1。栈里多了一组，d 加 1。空闲或成功——栈顶弹出，c 大于 0 的分组前面少了一组，c 减 1；d 减 1。 对照表看：时隙 1，A、B、C 的 c 都是 0，一起发，碰撞；抛硬币都是正面，c 仍是 0，d 变成 2。时隙 2，又碰撞，A 正面，B、C 反面，B、C 的 c 变成 1，d 变成 3。时隙 3，只有 A 的 c = 0，A 发，成功；B、C 的 c 减到 0，d 减到 2。……最后时隙 9，d = 1，栈顶是空的那一组，空闲，d 变成 0，结束。表里加粗的 0 就是发送的分组，破折号表示已经发完。 这里有隐含的前提：所有节点必须每个时隙都听反馈，而且听到的一致。新来的分组不能加入正在进行的分解期，因为它不知道 d。
