真实协议 ①：SLIP（串行线路 IP）

它是什么

早年用电话线和调制解调器拨号上网的数据链路协议（RFC 1055，1988 年），只负责一件事：把 IP 数据报装进帧里发出去。

和玩具协议的对应

路标 “~” → 字节 END = C0；转义字符 “\” → 字节 ESC = DB。

帧格式：END + IP 数据报 + END

C0

IP 数据报（任意个字节）

C0

END · 1 字节

不定长

END · 1 字节

END = C0H（1100 0000）

一帧的开始和结束。接收方一见到 C0，就知道到了帧的边界。

ESC = DBH（1101 1011）

转义字符。IP 数据报里如果碰巧出现 C0 或 DB，要用它来“改写”。

【2 分钟】 前面是玩具，现在看第一个真实的协议：SLIP，全称 Serial Line IP，串行线路上的 IP 协议。20 世纪 80 年代末，大家用电话线加调制解调器拨号上网，用的就是它。它只干一件事：把 IP 数据报装进帧，从串口发出去。 它和我们的玩具协议一一对应：路标 ~ 换成字节 END，十六进制 C0；转义字符 \ 换成字节 ESC，十六进制 DB。 帧格式极其简单：一个 END，后面跟着整个 IP 数据报，最后再来一个 END。 END = C0H，也就是 1100 0000，标出一帧的开始和结束。ESC = DBH，也就是 1101 1011，是转义字符。 问题和玩具协议一样：IP 数据报是任意字节，里面可能碰巧出现 C0 或 DB。下一页看 SLIP 怎么处理。 [补充：很多实现会在帧的开头也发一个 END，这样即使线路上有噪声，接收方也能先把噪声“冲掉”。课上可以不展开。]
