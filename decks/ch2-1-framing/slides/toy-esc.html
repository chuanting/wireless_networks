第二部分 · 面向字符的组帧

转义：给载荷里的特殊字符“加个前缀”

发送方

载荷里的 ~ 写成 \~；载荷里的 \ 写成 \\。

接收方

见到 \：丢掉它，下一个字符当普通数据；见到没有 \ 的 ~：路标。

① 原始载荷

A

~

B

\

C

5 个字符，其中 ~ 和 \ 是“特殊字符”

② 线路上

~

A

\

~

B

\

\

C

~

橙：路标；蓝：插入的转义字符

③ 接收方还原

A

~

B

\

C

与原始载荷完全一致 ✓

这样，线路上不带 \ 的 ~ 一定是路标，载荷可以是任意内容——透明传输做到了。

【3 分钟 · 本节最核心的例子】 解决办法：转义。引入一个新字符 \（叫“转义字符”）作为前缀。 发送方的规则：载荷里每遇到一个 ~，就在它前面加一个 \，也就是写成 \~；载荷里每遇到一个 \，也要在它前面加一个 \，也就是写成 \\。 接收方的规则：遇到 \，就把它丢掉，把紧跟着的那个字符原样当作数据；遇到没有 \ 前缀的 ~，才是路标。 例子：原始载荷是 A~B\C。 （点击）发送方处理：A 不变；~ 变成 \~；B 不变；\ 变成 \\；C 不变；再在两端加上路标 ~。线路上是：~ A \~ B \\ C ~，一共 9 个字符。蓝色的是我们插入的转义字符，橙色的是路标。 （再点击）接收方还原：先看到第一个 ~，是路标，帧开始；A 是普通字符；\ 后面的 ~ 是被转义的数据，保留 ~；B；再看到 \，它后面的 \ 是被转义的数据，保留 \；C；最后看到一个没有 \ 前缀的 ~，是路标，帧结束。还原出来是 A~B\C，与原来完全一致。 这就是“透明传输”：不管载荷里是什么，接收方都能原样还原。代价是：载荷里每出现一个特殊字符，就要多发一个字符。 [术语：这种做法，在字符型协议里叫“字符填充”或“字节插入”（byte stuffing / character stuffing）。]
