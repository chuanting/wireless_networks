第一个困难：普通无线设备发送时，自己发出的强信号会淹没远处的弱信号，因此难以像共享电缆那样一边发送、一边判断别人是否也在发送。

第二个困难：图中 A、C 都能联系 B，却彼此听不到。C 正向 B 发时，A 仍听到空闲，也开始发，结果两个信号在 B 处重叠。碰撞发生在接收端。

模型前提变了：此前额外假定了完全互听；图中 A、C 都能到达 B，却不满足这一条件，所以原模型不能直接套用。

碰撞发生在接收方：发送方听到的“空闲”，不等于接收方那里空闲。

无线端难以可靠地边发边检测，只能尽量错开发送机会，再借助接收方的确认判断是否送达。

【讲读提示】A 和 C 彼此听不到，却都能把信号送到 B。两端各自侦听为空闲时，同时发送仍会让 B 收到重叠信号。 【3 分钟】 最后说说无线局域网，也就是 Wi-Fi。它也是先听后说，但不用碰撞检测，有两个原因。 第一，难以边发边听。自己天线发出去的信号，比远处传来的别人的信号强得多，发送的时候根本听不到别人。 第二，隐藏终端。看图：A 和 C 都能和 B 通信，但 A 和 C 相距太远，互相听不到，虚线圆是各自的通信范围。C 正在向 B 发送时，A 侦听到的仍是“空闲”，也开始向 B 发，两个信号在 B 处碰撞。碰撞发生在接收方，发送方 A 根本听不到，就算能边发边听也没用。 这也纠正一个常见的误解：4.1 里说的“单跳”只表示每个发送者都能到达同一个接收方，并不保证它们彼此能听到。本章前面的模型额外假定了“完全互听”，才把隐藏终端排除在外；这里就是把这个假定去掉的情形。 【收束提示】无线端难以可靠地边发边检测，只能尽量错开发送机会，再借助接收方的确认判断是否送达。
