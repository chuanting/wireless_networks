Wi-Fi 的 CSMA/CA：随机退避 + 确认

先退避

信道空闲达到规定的间隔后，不马上发，先在竞争窗口里随机选一个退避计数。

冻结与恢复

计数只在信道空闲时递减；遇到忙就冻结，空闲后接着数。数到 0 才发。

确认

接收方成功后回 ACK。没收到 ACK，说明这次交换没有确认成功（不一定是碰撞），窗口加倍，重试。

RTS / CTS

先发短的 RTS，接收方回 CTS；听到 CTS 的邻居按其中的时长暂缓。减轻隐藏终端造成的长帧碰撞，但控制帧本身也会碰撞。

避免碰撞靠的是随机退避和预约，不是碰撞检测。

【3 分钟】 Wi-Fi 改用 CSMA/CA，CA 是 Collision Avoidance，碰撞避免。下面描述的是需要退避时的典型单播竞争过程，首次发送等边界细节在标准里另有规定。 一，信道空闲达到规定的间隔后，不马上发，而是先在竞争窗口里随机选一个退避计数。这避免了大家在信道刚空出来时一起冲上去，也就是 1-坚持的毛病。二，计数只在信道空闲的时隙里递减；遇到忙就冻结，空闲之后接着数；数到 0 才发送。这样等了很久的节点，下次不必从头再等，既公平又节省时间。三，接收方成功收到后，回一个确认 ACK；发送方没收到 ACK，说明这次交换没有确认成功，不能仅凭这一点断言一定发生了碰撞（也可能是噪声或 ACK 丢了），按规则把竞争窗口加倍再试，和以太网的指数退避类似。广播通常不逐帧 ACK。 四，对隐藏终端，可以先发一个很短的请求帧 RTS，接收方回一个 CTS，周围听到 CTS 的节点就知道信道将被占用多久，按其中的时长设置“虚拟载波侦听”并退让。C 不必听到 A 的 RTS，只要听到 B 的 CTS。这就是 4.1 讲的预约思想：用一次短帧的竞争，换一次长帧的无碰撞传输。但 RTS/CTS 不能消除所有冲突，控制帧本身也可能碰撞。 [参考：RFC 8325 第 2 节；Bianchi 对 802.11 DCF 退避冻结与恢复的分析。]
