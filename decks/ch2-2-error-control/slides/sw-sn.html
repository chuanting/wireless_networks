SN：我这一帧的编号

RN：我期望收到的下一帧的编号（= 已经正确收到的最大编号 + 1）

B 的规则

收到 SN = RN 的帧：交付，RN 加 1。收到 SN < RN 的帧：是重复，丢弃，但仍然回 ACK(RN)。

停等式里，SN 和 RN 只需要 1 位（模 2）：0、1 交替就够了。

【3 分钟 · 重点】 解决办法：给每一帧编一个序号，叫发送序号 SN；同时，接收方记住“我期望收到的下一帧是第几号”，叫接收序号 RN。每一帧里都带这两个域：SN 是这一帧自己的编号，RN 是“我期望收到的下一帧的编号”，也就等于已经正确收到的最大编号加 1。 接收方 B 的规则：收到 SN 等于 RN 的帧，是 B 正在等的新帧：交给上层，RN 加 1。收到 SN 小于 RN 的帧，说明是已经收过的重复帧：丢弃，但仍然回 ACK，告诉对方“我期望的是 RN”。 再看图，重复刚才的情形：A 发 DATA，SN = 0；B 收到，交付，RN 从 0 变成 1，回 ACK，RN = 1；但 ACK 丢了。A 超时，重发 SN = 0（橙色）；B 收到，发现 SN = 0 小于 RN = 1，是重复，丢弃，不再交付，但仍然回 ACK（RN = 1）；A 收到 ACK，RN = 1 大于自己的 SN = 0，说明 B 已经收到了，于是发下一帧，SN = 1。 一个有趣的问题：序号要多大？停等式里，同时在路上的帧最多只有 1 个（新帧或它的重发），所以序号只需 1 位：0、1 交替就够了。 [提示：现在 ACK 和数据帧用同一个帧格式（SN、RN、分组、CRC）；没有数据可发时，也可以发一个只有 RN 的短帧。]
