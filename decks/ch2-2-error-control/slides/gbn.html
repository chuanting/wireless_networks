窗口 n = 3。帧 1 丢了：2、3 被接收方丢弃，没有推进确认号的 ACK，窗口停在 1；超时后从 1 起重发 1、2、3。接收方只收按序的帧，RN 表示 RN 之前的帧都已收到（累计确认）。

先判断：窗口为 3，接收方已收帧 0、正在等帧 1。收到帧 2、3 后，RN 是多少？超时后重发哪些帧？

【3 分钟】 【先判断，再揭晓】先只显示问题，让学生写下 RN 和重发序列，并说明帧 2、3 是否交给上层。第一次点击显示时空图，核对 RN = 1、重发 1、2、3。第二次点击显示完整规则。追问：若想保留正确收到的 2、3，接收方要增加什么能力？下一页用选择重发回答。 返回 n（Go-Back-N）：错了一帧，从这一帧起全部重发。规则（窗口 n = 3）：A 可连续发最多 3 个未确认的帧；B 只接收按顺序到达的帧，其余丢弃；B 的 ACK 里的 RN 表示：RN 之前的帧都已收到，累计确认。 看图：帧 0 顺利到达，ACK RN=1 回来，窗口右滑，A 接着发帧 3。帧 1 丢了以后，B 收到 2、3，顺序不对，全部丢弃（灰色）；没有新的 ACK，A 的窗口停在 1。超时后（帧 1 发出后过了一个来回），A“退回”到 1，把 1、2、3 全部重发（红色）。这次 B 按序收到，依次交付，RN 变成 4。好处：B 不需要缓存乱序的帧，实现简单；代价：2、3 明明收对了，却要重发一遍。 算法细节：发送方维护 SNmin（最小的未确认序号）和 SNmax（下一个要分配的序号）；若 SNmax 小于 SNmin + n 且上层有新分组，就分配序号 SNmax 并加 1；收到无错的 ACK 且 RN 大于 SNmin，SNmin 变成 RN（窗口右滑）；SNmin 长时间不变，就从 SNmin 起重发。接收方和停等式的 B 一模一样。ACK 丢了没关系：累计确认，后面的 ACK 一到，前面丢的自动补上。快速反馈：B 发现帧序号不对，可以立刻回一个拒绝帧 REJ，A 不必等超时就回退重发，HDLC 里有。
