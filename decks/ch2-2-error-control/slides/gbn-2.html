返回 n 的算法，以及几个细节

发送方 A

SNmin = 窗口下沿（最小的未确认序号）；SNmax = 下一个要分配的序号。

• 开始：SNmin = SNmax = 0。

• 若 SNmax < SNmin + n，且上层有新分组：分配序号 SNmax，SNmax 加 1。

• 收到无错的 ACK 且 RN > SNmin：SNmin = RN（窗口右滑）。

• SNmin 长时间不变：从 SNmin 起重发。

接收方 B

• 置 RN = 0。

• 收到 SN = RN 的帧：交给上层，RN 加 1。其余帧丢弃。

• 收到任何正确的帧后，在有限时间内回一个带 RN 的帧。

（和停等式的 B 一模一样，只是 A 的窗口变大了。）

ACK 丢了没关系

累计确认：后面的 ACK 一到，前面丢的就自动补上。

快速反馈：REJ

B 发现帧序号不对，立刻回一个短帧（拒绝），A 不必等超时就回退重发。HDLC 里就有。

n 不能太大

出错时要重发 n 帧，n 越大浪费越多；但 n 太小又填不满管道。

【3 分钟】 把返回 n 的规则写完整。发送方记两个量：SN_min 是窗口的下沿，也就是最小的还没有被确认的序号；SN_max 是下一个要分配给新分组的序号。 开始时 SN_min = SN_max = 0。如果 SN_max 小于 SN_min + n（说明窗口还没满），并且上层有新分组，就给它分配序号 SN_max，SN_max 加 1。收到无错的 ACK，并且 RN 大于 SN_min，就把 SN_min 改成 RN（窗口右滑）。如果 SN_min 长时间不变，就从 SN_min 起重发。 接收方：置 RN = 0；收到 SN 等于 RN 的帧，交给上层，RN 加 1，其余的丢弃；收到任何正确的帧后，在有限时间内回一个带 RN 的帧。和停等式的接收方一模一样。 几个细节：第一，ACK 丢了没关系：累计确认——后面的 ACK 一到，前面丢失的就自动补上了。第二，快速反馈：B 发现帧序号不对，可以立刻回一个短帧叫 REJ（拒绝），A 不必等超时，立即回退重发。HDLC 里就有这个帧。第三，n 不能太大：出错时要重发 n 帧，n 越大浪费越多；但 n 太小又填不满管道。 [注：公式里的 SN_min 和 SN_max 可以只当成两个指针记住：窗口的左右边界。]
