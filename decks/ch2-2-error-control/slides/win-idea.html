【3 分钟】 滑动窗口的想法：发送方可以连续发多个帧，但“已经发出、还没有收到确认”的帧不能超过 n 个，n 叫窗口宽度。 看图（点击逐步演示）。12 个帧，编号 0 到 11，n = 5。 ① 开始：窗口是 [0, 4]，蓝色边框表示窗口内、可以发。窗口外的 5 到 11 暂时不能发。 ② 发送方连续发出 0 到 4（橙色）：窗口满了，不能再发 5，必须等确认。 ③ 收到 0 和 1 的确认（灰色表示已确认）：窗口的左边界右移到 2，窗口变成 [2, 6]，于是 5、6 可以发了。窗口就这样随着确认的到达，向右“滑动”。 窗口宽度 n 的含义：“已发未确认”的帧最多 n 个。停等式就是 n = 1 的特例。 顺便得到“流量控制”：如果接收方放慢确认的返回，发送方就会被窗口卡住，发送速度自然降下来。第 6 章会再回到这个话题。 [提示：n 应该多大？这要看管道能装多少帧，也就是 1 + 2a，后面“窗口取多大”一页会讲。]
