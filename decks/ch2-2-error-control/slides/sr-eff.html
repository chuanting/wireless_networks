第二部分 · ARQ 协议 · 效率比较

三种 ARQ 的效率：以卫星链路为例

选择重发：每帧只需重发出错的那一帧

平均每帧发送 1/(1 − p) 次，管道总是满的，所以（窗口足够大时）：

U = 1 − p

窗口不够大（n < 1 + 2a）时，再乘 n / (1 + 2a)。

三个公式（窗口足够大）

停等式

1 − p

1 + 2a

返回 n

1 − p

1 + (n − 1)p

选择重发

1 − p

例：卫星链路 a = 20，p = 0.1，窗口取 n = 41

停等式

2.2%

返回 n

18%

选择重发

90%

时延越大、误帧率越高，选择重发的优势越明显；代价是接收方要有缓存和排序能力。

【3 分钟】 选择重发的效率就很容易算了。每一帧只需要重发出错的那一帧，平均每帧发 1/(1−p) 次，管道总是满的，所以只要窗口足够大，U = 1−p。窗口不够大时，再乘 n/(1+2a)。 把三个公式放在一起（窗口足够大）：停等式 (1−p)/(1+2a)；返回 n (1−p)/[1+(n−1)p]；选择重发 1−p。 例：还是卫星链路，a = 20，p = 0.1，n = 41。 停等式：0.9/41 = 2.2%。 返回 n：0.9/(1+40×0.1) = 18%。 选择重发：90%。 差别巨大。时延越大、误帧率越高，选择重发的优势越明显。代价是接收方要有缓存和排序能力。 实际情况：在 a 很小的链路上（局域网），三种方式的差别不大，所以最简单的停等或返回 n 就够了；在卫星、洲际长链路上，选择重发才划算。 [验算：0.9/41 = 0.02195；0.9/(1+40×0.1) = 0.18；选择重发 1−0.1 = 0.9。]
