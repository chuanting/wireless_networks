第二部分 · ARQ 协议 · 序号的取值范围

序号不能无限增长：模 m 之后，窗口不能太大

序号域只有几个比特

序号用模 m 表示，例如 3 位序号：0、1、…、7、0、1、……（m = 8）。

窗口 n 不能太接近 m，否则接收方分不清新帧还是旧帧的重发。

结论

返回 n：n ≤ m − 1

选择重发：n ≤ m / 2

HDLC：m = 8（3 位序号），返回 n 的窗口最大 7。

反例：返回 n，m = 8，窗口 n = 8（太大）

【3 分钟】 实际协议里，序号域只有几个比特，所以序号是模 m 循环的：3 位序号，就是 0 到 7，再回到 0。这就带来一个问题：窗口 n 不能太大，否则接收方会分不清“新帧”和“旧帧的重发”。 看反例：返回 n，序号模 8（m = 8），窗口也取 8。 第一轮 A 发 8 帧，序号 0 到 7，全部被 B 正确收到，B 的 RN 回到 0（因为 8 取模是 0）。 情形 A：ACK 全部到达，A 发新的 8 帧，序号还是 0 到 7。 情形 B：ACK 全部丢失，A 超时，重发同样的 8 帧，序号也是 0 到 7。 B 收到的序号完全一样，但意义完全不同：一个是新帧，一个是重发。B 没法区分，必然出错。所以返回 n 的窗口必须小于 m，n ≤ m−1。 选择重发更严格：B 也有一个窗口，要避免新旧窗口的序号重叠，所以 n ≤ m/2。 HDLC：序号 3 位，m = 8，返回 n 的窗口最大是 7；扩展格式用 7 位序号，窗口最大 127。 [提示：这个结论下节（2.3）讲 HDLC 时还会用到，“模 8”和“窗口最大 7”要记住。]
