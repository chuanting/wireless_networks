窗口为 0：停发

应用取走数据

发送方可以发到 ack + win：应用不取，这个边界就不动（4000）；应用取走数据，边界右移（8000）。

接收窗口保护的是接收方的缓冲区。

【3 分钟】 流量控制：接收方来不及处理，怎么让发送方慢下来？TCP 的办法：接收方在每个 ACK 里，把自己缓冲区剩下的空间写进 win 字段，叫接收窗口。发送方必须遵守：能发送的范围是从 ack 到 ack + win，也就是已确认位置之后 win 个字节。用 ack 作左边界来想，比说“在途字节数不超过 win”更清楚。 看图：B 的缓冲区共 4000 字节，应用暂时不取数据。（图里 A 每次只发两段，是为了图清楚；它也可以一开始就把 4000 字节全发出去。）A 发了 seq = 0 和 seq = 1000 两段，B 收下后：ack = 1000、win = 3000，再 ack = 2000、win = 2000。A 看到 win，右边界是 ack + win = 4000，于是发 seq = 2000、3000。B 又收下两段：ack = 3000，win = 1000；ack = 4000，win = 0，缓冲区满了。右边界一直是 4000，没动。A 看到 win = 0，停下（红色括号）。 过了一会儿，应用把缓冲区里的数据取走，B 发一个窗口更新：ack = 4000，win = 4000，右边界移到 8000，A 恢复发送 seq = 4000。 一个细节：如果这个窗口更新丢了，A 会永远等下去，B 也在等 A 发数据，死锁。所以 A 在窗口为 0 时会定时发很小的探测报文（零窗口探测），催对方回复当前窗口。 对照 2.3：HDLC 用 RNR 和 RR，一个“停”一个“走”，是开关；TCP 用一个数值，告诉对方“我还能收多少”，更精细。 [验算：程序模拟接收缓冲区，ack + win 依次为 4000、4000、4000、4000、8000。]
