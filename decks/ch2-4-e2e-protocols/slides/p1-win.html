第一部分 · 网络层

网络层为什么也要编号、确认和窗口？

① 编号：认出“谁是谁”

在数据报网络里分组可能乱序、丢失、重复。

3 号比 2 号先到 → 按编号重排；5 号没来 → 知道丢了；4 号来了两次 → 丢掉一个。

② 确认：告诉发送方“收到哪了”

接收方回“我已收到 0–4 号”（累积确认，和 2.2 的 RN 一样）。

③ 窗口：限制“在途”的分组数

发送方最多有 n 个未确认的分组在网络里：

• 流量控制：接收方来不及处理，就不确认，发送方自动停下。

• 保护网络：不让一个会话把网络塞满。

窗口和速率有什么关系？（推导）

设窗口为 n 个分组，一个往返时间为 T。

发送方发出 n 个后，必须等确认回来才能继续：最快每隔 T 发 n 个。

速率 ≤ n / T　（分组 / 秒）

设链路最大速率为 R（分组 / 秒）。要跑满，需要 n / T ≥ R，即

n ≥ R · T

R · T 就是“管道”里能同时装下的分组数。这和 2.2 的 n ≈ 1 + 2a 是同一个结论。

【3 分钟】 链路层有的零件，网络层的端到端协议也要有。三个：编号、确认、窗口。 编号：在数据报网络里，同一次会话的分组可能走不同的路，所以可能乱序、丢失、重复。有了编号，接收方可以：3 号比 2 号先到，按编号重排；5 号一直没来，知道它丢了；4 号来了两次，丢掉一个。 确认：接收方回一个“我已收到 0 到 4 号”。这叫累积确认，和 2.2 里的 RN 是一回事。 窗口：发送方最多允许有 n 个“未确认”的分组在网络里。窗口有两个作用：一是流量控制——接收方来不及处理时，就不确认，发送方的窗口用完了，自然停下；二是保护网络——不让一个会话把整个网络塞满。 右边推导窗口和速率的关系。设窗口是 n 个分组，一个往返时间是 T。发送方发出 n 个分组后，必须等确认回来才能继续发。所以最快的情况是：每隔 T 秒发 n 个。因此速率不会超过 n 除以 T。 再设链路能跑到的最大速率是 R，单位是分组每秒。要跑满，需要 n/T 大于等于 R，也就是 n 大于等于 R 乘 T。R 乘 T 是什么？就是“管道”里能同时装下的分组数。这和 2.2 里讲的“窗口 n 约等于 1 加 2a”是同一个结论，只是换了一种写法。 下一页算一个具体的例子，看看这个窗口到底要多大。
