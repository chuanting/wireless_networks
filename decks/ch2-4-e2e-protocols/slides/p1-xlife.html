X.25：虚电路的一生

① 呼叫建立

Call Request → Call Accepted。路径上每个节点登记 VC 表，分配号码。

② 数据传输

Data 分组带 P(S) / P(R)；没有数据可捎带时，用 RR 单独确认（和 HDLC 的 RR 一样）。

③ 清除

Clear Request → Clear Confirmation。每个节点删除 VC 表项。

和 2.3 的 SABM / UA → 数据 → DISC / UA 是同一个模式：建立、传输、拆除。

【3 分钟 · 可压缩】 看一条 X.25 虚电路的一生。图里 A 是主叫，B 是被叫，中间的网络节点省略了。 第一阶段，呼叫建立：A 发一个 Call Request，意思是“我要和 B 建立一条虚电路”。这个请求沿路经过每一个节点，每个节点登记一条 VC 表项，分配一个号码。B 如果同意，回 Call Accepted，虚电路建好了。 第二阶段，数据传输：A 发两个 Data 分组，P(S) 分别是 0 和 1，P(R) 都是 0，表示“我还没收到你的数据”。B 没有数据要发，就用一个 RR 单独确认：RR、P(R) 等于 2，意思是“0 到 1 号都收到了，期待 2 号”。这里的 RR 和 2.3 学的 HDLC 的 RR 含义一样。 第三阶段，清除：A 发 Clear Request，B 回 Clear Confirmation，路径上每个节点把 VC 表项删掉。 对照 2.3：HDLC 是 SABM 加 UA 建立、传数据、DISC 加 UA 拆除；X.25 是 Call Request 加 Call Accepted、传数据、Clear Request 加 Clear Confirmation。是同一个模式：建立、传输、拆除。区别是，这里的“建立”不是在一条链路上，而是在一条经过很多节点的路径上。 [提示：如果节点故障、VC 表丢了怎么办？X.25 有 Reset 和 Restart 分组，让两端重新同步——和 2.3 的初始化是同类问题。]
