自己动手：看见 TCP

基础

抓一次握手

用 Wireshark 或 tcpdump 抓下“访问一个网页”的包，找到三次握手：记下三个报文的标志、seq、ack。

检验：第二个报文的 ack 恰好是第一个的 seq + 1；第三个报文的 ack 是第二个的 seq + 1。

中级

自己算 RTO

用 Python 的 socket 做一个回声程序，测 20 个 RTT 样本，按 RFC 6298 算 SRTT、RTTVAR、RTO，画出曲线。

检验：Linux 上用 “ss -ti” 看真实连接的 rtt、rto，量级应与你的结果接近；样本稳定时 RTO 应明显小于初值。

进阶

小型 TCP 模拟器

模拟丢包、乱序的链路，实现累积 ACK、乱序缓存、超时重传、快速重传；统计吞吐随丢包率的变化。

检验：单个报文丢失时，应在收到第 3 个重复 ACK 后重发，而不是等超时。

想挑战更多？给模拟器加上接收窗口和窗口放大，验证 “吞吐 ≤ 窗口 / T”；或者在握手里故意放进一个迟到的旧 SYN，看你的实现能否识破。

【选做 · 课上只需 1 分钟介绍】 这页是给想动手的同学准备的，不在课上做。 基础：用 Wireshark 或者 tcpdump，抓一次访问网页的包。例如在 Linux 上，一个终端运行 tcpdump，过滤只看带 SYN 或 FIN 标志的包；另一个终端用 curl 访问一个网页。就能看到三次握手：第一个包是 SYN，第二个是 SYN+ACK，第三个是 ACK。检验：第二个包的确认号，恰好是第一个包的序号加 1。因为 SYN 占一个序号。 中级：自己动手算 RTO。用 Python 的 socket 做一个简单的回声程序，客户端发一个小包，服务器原样返回，测量往返时间，测 20 个样本。然后按照 RFC 6298 的公式，第一个样本 SRTT 取它本身，RTTVAR 取一半，之后按 α = 1/8，β = 1/4 更新，RTO 等于 SRTT 加 4 倍 RTTVAR。画出曲线，和本节的图对照。如果有 Linux，ss -ti 命令能看到真实连接的 rtt 和 rto，可以对照量级（真实系统的 RTO 有 200 毫秒的下限）。 进阶：写一个小型 TCP 模拟器：模拟一条会丢包、乱序的链路，实现累积确认、乱序缓存、超时重传和快速重传，统计吞吐随丢包率的变化。检验：单个报文丢失时，应该在收到第 3 个重复 ACK 后重发，而不是等超时。 更进一步：加上接收窗口，验证“吞吐不超过窗口除以往返时间”；或者在握手里故意放进一个迟到的旧 SYN，看你的实现能不能识破。 [提示：这些练习不要求提交，愿意做的同学可以课后找老师交流。]
