【选做 · 课上只需 1 分钟介绍】 这页是给想动手的同学准备的，不在课上做。 基础：用 Wireshark 或者 tcpdump 抓一次访问网页的包。例如在 Linux 上，一个终端运行 tcpdump，过滤只看带 SYN 或 FIN 标志的包；另一个终端用 curl 访问一个明确走 TCP 的网页（注意 HTTP/3 走的是 UDP，要选 HTTP/1.1 或 HTTP/2）。就能看到三次握手：第一个包是 SYN，第二个是 SYN+ACK，第三个是 ACK。检验：第二个包的确认号，恰好是第一个包的序号加 1，因为 SYN 占一个序号；抓包软件默认显示相对序号，要看真实值，在设置里关掉相对序号。 中级：自己算 RTO。用 Python 的 socket 做一个简单的回声程序，客户端发一个小包，服务器原样返回，测量往返时间，测 20 个样本。然后按照 RFC 6298 的公式：第一个样本 SRTT 取它本身，RTTVAR 取一半，之后先算 RTTVAR（β = 1/4）、再算 SRTT（α = 1/8），RTO 等于 SRTT 加 4 倍 RTTVAR。画出曲线，和课上的图对照。在 Linux 上，ss -ti 命令能看到真实连接的 rtt 和 rto，可以对照量级（真实系统的 RTO 有 200 毫秒的下限）。 进阶：写一个小型 TCP 模拟器：模拟一条会丢包、乱序的链路，实现累积确认、乱序缓存、超时重传和快速重传，统计吞吐随丢包率的变化。检验：缺口后至少到达三段、产生足够重复 ACK 时，经典快速重传在第 3 个重复 ACK 后触发；否则可能仍要等超时。 改变一个假设：把“丢失一段”改成零丢包、仅让该段晚于后面三段到达，其他参数保持相同。记录重复 ACK、快速重传和原段的实际到达时刻，识别因乱序触发的多余重传。三个重复 ACK 是经典触发规则，不是丢包的严格证明。 [提示：这些练习不要求提交，愿意做的同学可以课后找老师交流。]
