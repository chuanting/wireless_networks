窗口给速率设了上限

①

窗口是 n 个分组，一个往返时间是 T。发出 n 个以后必须等确认，所以每个往返最多发 n 个：

速率 ≤ n / T

②

链路每秒最多能发 R 个分组。要跑满，需要：

n / T ≥ R

③

也就是：

n ≥ R·T

管道里能同时装下的分组数

对照 2.2：R·T = (TD + 2Tp) / TD = 1 + 2a，和停等、返回 n 里的 n ≥ 1 + 2a 是同一个结论。

窗口不够：n 小于 R·T 时，利用率是：

U = n / (R·T)

带宽时延积：管道里同时能装多少个分组，窗口就得有多大。

【3 分钟】 链路层有的零件，网络层的端到端协议也要有：编号、确认、窗口。编号让接收方认出乱序、丢失和重复；确认告诉发送方“收到哪了”；窗口限制“在途”的分组数。窗口有两个作用：一是流量控制，接收方来不及，就不确认，发送方的窗口用完了自然停下；二是保护网络，不让一个会话把网络塞满。 窗口和速率什么关系？设窗口是 n 个分组，一个往返时间是 T。发送方发出 n 个分组后必须等确认才能继续，所以每个往返最多发 n 个，速率不超过 n/T。设链路每秒最多能发 R 个分组。要跑满，需要 n/T 不小于 R，也就是 n 不小于 R 乘 T。 R 乘 T 是什么？管道里能同时装下的分组数，叫带宽时延积。它和 2.2 里的 n ≥ 1 + 2a 是同一个结论：R = 1/TD，T = TD + 2Tp，所以 R·T = (TD + 2Tp)/TD = 1 + 2a。窗口比 R·T 小，利用率就是 n/(R·T)；比它大，无差错时也不会更高。
