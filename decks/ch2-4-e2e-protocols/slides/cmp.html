同样的零件，不同的环境：HDLC 与 TCP

链路层：HDLC（2.3）

运输层：TCP

编号对象

帧，3 位（模 8）

字节，32 位

确认

RN：期待的下一帧

ack：期待的下一字节（累积）

窗口

固定，最大 7（扩展模式 127）

接收方通告 rwnd，再加发送方的 cwnd

超时

按链路配置

自适应 RTO

出错重传

返回 n，REJ 加速

超时重传，快速重传，SACK

流量控制

RR / RNR：开关

win：具体数值

建立与拆除

SABM / UA；DISC / UA

三次握手 + 变化的 ISN；四次挥手 + TIME_WAIT

原理一脉相承；环境越恶劣，机制越复杂。

【3 分钟 · 重点】 把今天的 TCP 和 2.3 的 HDLC 放进同一张表。编号：HDLC 对帧编号，3 位，模 8；TCP 对字节编号，32 位。确认：都是累积的，RN 是期待的下一帧，ack 是期待的下一字节。窗口：HDLC 固定，最大 7，扩展模式 127；TCP 由接收方动态通告，再加上发送方的拥塞窗口。超时：HDLC 按链路配置；TCP 自适应。出错重传：HDLC 是返回 n，REJ 可以加速；TCP 是超时重传、快速重传，还有 SACK。流量控制：HDLC 用 RNR 和 RR，是开关；TCP 用 win，是具体数值。建立与拆除：HDLC 的 SABM 加 UA，DISC 加 UA；TCP 是三次握手加变化的初始序号，四次挥手加 TIME_WAIT，它们是 2.3 里“初始化”问题的升级版。 为什么复杂这么多？环境：HDLC 在点到点的链路上，时延固定，帧不乱序，也不会“迟到很久”；TCP 在多跳的网络上，时延多变，分组会乱序、重复，旧分组还会在网络里游荡很久。 对照的目的是建立可迁移的机制理解，而不是把每一层记成一张字段表。（HDLC 的扩展格式有更大的序号空间；TCP 的计时器也不都是自适应的。）
