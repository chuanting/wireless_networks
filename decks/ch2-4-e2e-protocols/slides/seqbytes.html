TCP 给字节编号

字节 1000–1999

seq = 1000

收到后 ack = 2000

字节 2000–2999

seq = 2000

收到后 ack = 3000

字节 3000–3999

seq = 3000

收到后 ack = 4000

字节 4000–4999

seq = 4000

收到后 ack = 5000

seq：这一段第一个字节的编号。

ack：期待收到的下一个字节的编号，而且是累积的：ack = 3000 表示 3000 之前的字节都收到了。

另外：SYN 和 FIN 各占 1 个序号；纯 ACK 不占序号。

按字节编号，所以重传时可以重新分段、合并。

【3 分钟 · 重点】 TCP 怎样编号？和 HDLC 不一样：HDLC 对帧编号，3 位；TCP 对字节编号，32 位。 图里：字节流被切成每段 1000 字节的报文段。第一段装的是第 1000 到 1999 号字节，它的序号 seq 就是 1000，也就是这一段第一个字节的编号。确认号 ack 的意思是“我期待收到的下一个字节的编号”，而且是累积的：收到前两段（1000 到 2999）后，B 回 ack = 3000，意思是 3000 之前的字节我都收到了，现在要 3000。 两个细节。一，SYN 和 FIN 各占一个序号（后面的握手、挥手会用到），纯 ACK 不占序号。二，ACK 表示接收端的 TCP 已经收到了连续的一段前缀，不表示应用已经把它读走。 为什么按字节、不按段编号？因为段的大小可以变：重传时可以把几个小段合并成一个大段重发，字节的“身份”不变。（序号按 2^32 回绕；回绕和窗口的关系，在后面讲窗口放大时再算。）
