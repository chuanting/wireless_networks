第二部分 · 对照

同样的零件，不同的环境：HDLC 与 TCP

比较项

链路层：HDLC（2.3）

运输层：TCP

编号对象

帧，3 位（模 8）

字节，32 位

确认

RN：期待的下一帧（累积）

ack：期待的下一字节（累积）

窗口

固定，≤ 7（扩展模式 127）

接收方动态通告 + 拥塞窗口

超时

固定值

自适应 RTO

出错重传

返回 n；REJ 加速

超时重传 + 快速重传 + SACK

流量控制

RNR / RR（开关）

win（具体数值）

建立

SABM / UA：2 个报文

三次握手 + 随机 ISN

拆除

DISC / UA

四次挥手 + TIME_WAIT（2MSL）

环境

点到点；时延固定；不乱序

多跳；时延多变；乱序、重复、旧分组

原理一脉相承（编号、累积确认、窗口、超时重传、初始化）；环境越恶劣，机制越复杂：自适应的 RTO、握手里的随机数、TIME_WAIT 都是因为分组可能迟到、乱序、重复。

【3 分钟 · 重点】 把今天的 TCP 和 2.3 的 HDLC，放进同一张表里对照。这是本节最重要的一页之一。 编号：HDLC 对帧编号，3 位，模 8；TCP 对字节编号，32 位。 确认：都是累积的。HDLC 的 RN 是“期待的下一帧”；TCP 的 ack 是“期待的下一字节”。 窗口：HDLC 固定，最多 7，扩展模式 127；TCP 由接收方动态通告，再加上拥塞窗口。 超时：HDLC 可以设固定值；TCP 要自适应，根据测量的往返时间不断调整。 出错重传：HDLC 是返回 n，REJ 可以加速；TCP 是超时重传，加上快速重传，还有 SACK。 流量控制：HDLC 用 RNR 和 RR，是开关；TCP 用 win，是具体数值。 建立：HDLC 的 SABM 和 UA，两个报文；TCP 是三次握手，加上随机的初始序号。拆除：HDLC 的 DISC 和 UA；TCP 是四次挥手，还有 TIME_WAIT 等 2MSL。注意最后这两行，用橙色标出：它们都是 2.3 里“初始化”问题的升级版，原因就在最后一行：环境。 环境：HDLC 在点到点的链路上，时延固定，帧不会乱序，也不会“迟到很久”；TCP 在多跳的网络上，时延多变，分组会乱序、重复，旧分组还会在网络里游荡很久。 结论：原理一脉相承，环境越恶劣，机制越复杂。这就是为什么 TCP 比 HDLC 复杂得多——而不是因为设计得不好。 [提示：期末考试常考这类对比题。]
