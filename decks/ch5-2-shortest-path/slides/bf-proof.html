为什么三轮就够？

图里只有四个点，每段代价都为正。走四段就会重复经过某个点，删去绕圈部分一定更便宜。最多三段已经包括最短路。

A 给目的地 D 填上下一跳 C、总代价 5。比较最后一段也能核对这个 5：经 B 是 3 + 2，经 C 是 2 + 8。

【3 分钟】 先遮住蓝线的终点，请大家只按“上一站”的记录从 D 往回读 D、B、C、A。正向重读是 A、C、B、D。A 发包时只需要写下一跳 C，再在纸上把 2+1+2 加一遍验证总代价 5。 问学生还要不要试四段。这里有四个节点，一条走四段的路线会列出五个节点名，至少有一个重复。因为每段代价都为正，绕一圈就多付代价，删去这个圈会更短。这说明本例第三轮算完就已得到最短路。若程序靠“整轮没有改变”来判断停止，可以再算一轮核对。 如果学生见过“贝尔曼方程”，现在可以给这个名字：最短路到 D 的最后一段只能来自 B 或 C，稳定后的最短距离必须是“到上一站的最短距离加上最后一段”的最小值。本例就是 5 = min(3+2, 2+8)。如果去上一站还有更短的走法，把最后一段接在那条更短的路上也会更便宜。这就是刚才自然用到的准则。 现在换回 5.1 的六路由器图。如果大家都要去同一个终点，能否把刚才“从哪里来”的问题反过来，改问“下一步交给谁”？
