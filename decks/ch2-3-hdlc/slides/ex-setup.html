为什么要先握手

让两端的状态（模式、序号）对齐，否则 SN、RN 可能对不上（第四部分会详细讲）。

【3 分钟】 第一个场景：先“握手”建立链路，再发数据。 第一步，建立：A 发一个 SABM（Set Asynchronous Balanced Mode，“我们进入异步平衡模式吧”），P = 1，要求对方回答；B 同意，回一个 UA（无编号确认），F = 1。至此，双方的 SN 和 RN 都置 0，链路进入 UP 状态。 第二步，传数据：A 连续发 I(0,0) 和 I(1,0)，两个 I 帧，SN 分别是 0 和 1，RN 都是 0（A 还没有收到对方的任何数据）。B 没有数据要发，没法捎带确认，就用 RR(2) 单独确认：2 之前的帧——也就是 0 和 1——都收到了。 为什么要先握手？为了让两端的状态——工作模式、序号——对齐。如果不握手，直接发数据，B 可能还停留在上次通信遗留的序号状态，SN、RN 就对不上了。这个问题第四部分会详细讲。 [提示：这个场景对应 2.2 里的“返回 n”：A 连续发两个帧，B 一个累计确认。]
