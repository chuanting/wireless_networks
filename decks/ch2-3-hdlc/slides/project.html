选做：用代码“玩”一遍 HDLC

①

封装一个帧：地址 03、控制 00、信息 Hi：算 16 位 FCS（CRC-16/X-25），做比特插入，加上两端 Flag

FCS = AF72

“123456789” 的 CRC 应为 906E

②

控制域解码器：输入教学记法的 8 位控制域，输出 I、S、U 和各字段

用课堂练习的 4 个控制域检验

③

链路模拟器：返回 n，窗口 n，丢包概率 p，接收方发 REJ，统计利用率

≈ (1 − p) / (1 + 2ap)

n = 1 + 2a

怎么检验：解封装时，对整帧（含 FCS）再算一遍 CRC，应得到固定的余数；翻转任意一位，应检出错误。

改变一个假设：让节点重启时仍有旧 ACKI 在途。比较无随机数和带随机数的初始化，记录两端状态以及旧数据是否交给上层。

帧的字节顺序和每个字段的位顺序最容易写错：位 1 先发，FCS 先发低字节。

【选做 · 课上只需 1 分钟介绍】 这页是给想动手的同学准备的，不在课上做。 基础：封装一个 HDLC 帧。用 Python 把“地址 0x03、控制 0x00、信息 Hi”装成帧：算 16 位 FCS（CRC-16/X-25：多项式 0x1021 的反射形式，初值 0xFFFF，结果取反），再做比特插入，加上两端 Flag。检验：对 “123456789” 算出的 CRC 应为 0x906E；本例 FCS = 0xAF72，先发低字节 72，再发 AF。 中级：控制域解码器。输入采用课堂教学记法的 8 位控制域，字段内部按左高右低解释；输出：I、S 还是 U 帧；SN、RN、P/F，S 帧的类型（RR / REJ / RNR / SREJ）。检验：用课堂练习的 4 个控制域检验；再自己编 3 个，交给同桌检查。若处理真实线路的逐位记录，先按线路位序还原各字段，不能直接套用教学记法的解码器。 进阶：小型链路模拟器。模拟 A 到 B 的返回 n 协议：窗口 n，丢包概率 p，出错后接收方发 REJ，发送方回退重发；统计链路利用率。检验：n = 1 + 2a 时，应接近 (1 − p)/(1 + 2ap)，例如 a = 3、n = 7、p = 0.1 时约 0.56；再把 p 从 0.01 调到 0.2，看利用率怎样变化。改变一个假设：原实验初始化前没有旧帧，现让一个旧 ACKI 在节点重启后才到达。先复现误入 UP 和旧数据被交付，再给 INIT、ACKI 增加相同的随机标记。两次使用同一条故障时间线，记录两端状态和交付序列；随机数碰撞的情形另行统计。
