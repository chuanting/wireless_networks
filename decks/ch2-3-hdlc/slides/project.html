自己动手：用代码“玩”一遍 HDLC

基础

封装一个 HDLC 帧

用 Python 把“地址 0x03、控制 0x00、信息 Hi”装成帧：算 16 位 FCS（CRC-16/X-25：多项式 0x1021 的反射形式，初值 0xFFFF，结果取反），再做比特插入，加上两端 Flag。

检验：对 “123456789” 算出的 CRC 应为 0x906E；本例 FCS = 0xAF72，先发低字节 72，再发 AF。

中级

控制域解码器

输入 8 个比特，输出：I、S 还是 U 帧；SN、RN、P/F，S 帧的类型（RR / REJ / RNR / SREJ）。

检验：用第二部分课堂练习的 4 个控制域检验；再自己编 3 个，交给同桌检查。

进阶

小型链路模拟器

模拟 A 到 B 的返回 n 协议：窗口 n，丢包概率 p，出错后接收方发 REJ，发送方回退重发；统计链路利用率。

检验：n = 6、p = 0.1 时，应接近 (1 − p) / (1 + (n − 1)p) = 0.6；再把 p 从 0.01 调到 0.2，看利用率怎样变化。

想挑战更多？给模拟器加上 RNR 流量控制和随机数初始化，复现“旧 ACKI 混进新一轮”的故障，再验证随机数怎样把它挡住。

【选做 · 课上只需 1 分钟介绍】 这页是给想动手的同学准备的，不在课上做。 基础：用 Python 把一个 HDLC 帧拼出来。FCS 用 HDLC 的 CRC-16，也就是 X-25 版本：多项式 x 的 16 次方加 x 的 12 次方加 x 的 5 次方加 1，反射形式 0x8408；初值 0xFFFF；最后结果取反。检验办法：对字符串 123456789 算出来应该是 0x906E。本例的帧字节：03 00 48 69，FCS 是 0xAF72，传输时先发低字节 0x72，再发 0xAF，所以整个帧（不含 Flag）是 03 00 48 69 72 AF。这个例子里没有连续 5 个 1，所以比特插入不会插入任何位；可以自己换个数据，造出连续的 1 来测试。再检查一遍：把整帧（含 FCS）一起再算一次，结果是个固定的“余数” 0xF0B8，不等于这个值就说明有错。 中级：控制域解码器，对应第二部分的课堂练习，可以用那 4 个控制域检验。注意：书写时 SN、RN 按“左高右低”读，传输时低位在前。 进阶：做一个小的模拟器：发送方连续发帧，每个帧以概率 p 出错；接收方发现序号不对就发 REJ，发送方退回重发。每个错误浪费 n 个帧时间，所以利用率应接近 (1 − p) / (1 + (n − 1)p)。n = 6、p = 0.1 时是 0.6（我用一个简单模拟验证过：0.600）。把 p 调到 0.01，是 0.943；调到 0.2，是 0.4。 更进一步：加上 RNR 流量控制，或者复现今天讲的“旧 ACKI”故障，再看随机数怎样挡住它。 [提示：这些练习不要求提交，愿意做的同学可以课后找老师交流。]
