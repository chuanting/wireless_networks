Live demo：反馈怎样放大网络时延？

让同一任务在 CPU 与 I/O 间往返，观察访问流量、瓶颈与全网 Little 定理。

课堂实验：外部每秒仍进入 1 个任务，为什么内部会忙不过来？

外部任务先到 CPU；CPU 服务后以概率 p 去 I/O，其余离网。I/O 完成后返回 CPU。每次访问独立抽取指数服务时间。

① 教材例子：p = 0.75

【5 分钟 · 现场演示】 先点“下一事件”跟随任务编号：外部进入 CPU，CPU 完成后以 p 去 I/O，I/O 完成后一定返回 CPU；只有 CPU 的另一条分支才离网。同一任务可以反复出现，每次服务重新独立抽取指数时间。节点访问次数不能当作进入网络的新任务数。 ① 教材例子：外部 γ = 1，CPU 服务率 8，I/O 服务率 5，p = 0.75。解 λ_CPU = γ + λ_IO，λ_IO = p λ_CPU，得访问率 4 和 3，负荷 0.5 和 0.6；平均人数 1 和 1.5，所以网络 T = (1 + 1.5)/1 = 2.5 秒。快进几次，观察有限样本统计在理论附近波动。仿真从空系统开始，尚未排空时 T 只包括已经离网的任务，N 按时间平均，二者不能直接用于有限样本恒等式。 ② 点“增加反馈”。外部输入仍为 1，只把 p 调到 0.85，所需访问率变成 6.667 和 5.667；I/O 服务率只有 5，负荷超过 1。快进观察 I/O 积压。这里流量方程解表示处理全部输入所需的访问量；过载时实测访问率受到服务能力限制，不必等于方程解。持续输入时没有稳态平均时延，不能把负分母代进稳态公式。 ③ 点“升级 I/O”，将 I/O 服务率从 5 提高到 10，保持 p = 0.85；两个节点恢复稳定。CPU 平均人数 5，I/O 平均人数 1.307692，T = 6.307692 秒。这比过载状态好，但仍慢于原 p = 0.75 的 2.5 秒，原因是任务往返更多且 CPU 更忙。也可点“减少反馈”比较减少工作量的效果。 ④ 运行一段后点“停止到达并排空”，可再点“立即排空”。完成所有已经进入的任务后，用从 0 到最后一个离网时刻的同一观察窗口核对 N = γ实测 × T；γ实测 = 完成任务数 / 观察时长，不是输入框里用于生成到达的参数。全网平均时延必须用外部进入率，不可除以 CPU 与 I/O 的访问率之和；重复访问会重复计数。过载后停止到达也能排空并满足有限样本关系，这不代表持续输入时稳定。 模型假设：外部泊松到达，两节点每次服务相互独立且为指数分布；先来先服务、无限缓冲、瞬时转移。改参数会重置，预设固定随机种子方便课堂复现。总览、讲者预览和打印保留实验说明。
